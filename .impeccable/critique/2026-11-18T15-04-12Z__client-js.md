## Design Specificity

内容层真特异，形式层是宿主风格的通用看板。

特异：阶段门=可审计推断（连措辞都在自我限制）；唯一下一步三层（label/instruction/reason），把理由当一等公民；行动层用权限梯度换诚实；数据诚实性做成界面元素（"数字可能偏低"、"仍按全部任务计算"、"下面是 22:41 的数据"）。

通用：顶栏+卡片+表格骨架、chip、7 段进度线、12px 灰色标题。缺"到哪了"的量化语言（没有 5/7、没有三级状态）。

评级 B+：取舍对，但形式没承担取舍的视觉后果。

## Priority Issues

### [P0] 首屏对"卡在哪"给出互相矛盾的答案，绿色 chip 会骗人
chip 只看 totals.blocking → 0 显示绿色「无阻塞」；卡2 恒有 current 门，而 v1 的"验效果/发出去"写死 hit:false → 全绿项目变成「卡在「验效果」：验收表未接入（第二版）」。同屏三套说法（无阻塞 / 卡在验效果 / blocking 表头）。有 warnings 时 chip 仍绿。且"卡在验效果"是用户无法处理的卡点。
修法：chip 区分 degraded/unknown（warnings 或 error 时显示"状态待确认"，虚线边框）；卡2 对"验效果/发出去"改口径为「下一阶段：…」（第二版接入，当前不影响），只有前五门说"卡在"。

### [P1] 顶栏时间戳挂 aria-live，每 8 秒插播一次
client.js:372 `aria-live="polite"` 包着 `更新于 HH:MM:SS`，generatedAt 每轮都变 → 读屏每 8 秒被打断一次。同 header 还有 chip 的 role="status"。
修法：时间戳去掉 aria-live；loading 文案独立 `pc-sr` role="status"；`.pc-muted` 加 `font-variant-numeric: tabular-nums` 防秒数跳动抖宽。

### [P1] 账本英文枚举上屏，缺失值渲染成"让人安心的绿色 0"
`task.status` 原值（in_progress）、`#13 fix`、表头 blocking；`String(bugs.blocking == null ? 0 : bugs.blocking)` 配 pc-ok 绿色 → 读不到 = 0 = 绿。
修法：TASK_STATUS / VERDICT 映射表；null 显示「—」muted 不给绿色；表头 blocking → 待修，与 chip 同源术语。

### [P2] 主按钮文案承诺了它没做的事；跳转后焦点与项目身份都丢
按钮「让 AI 执行下一步」实际只 setPending + selectPanel('conversation')，不执行任何动作；跳转后原按钮卸载焦点落 body；dock 只有 label 无项目名；pending 跨项目存活。
修法：文案改「去对话发送」；pending 带 projectPath/projectName 并在 dock 显示；Page 卸载或 selected 变化时清 pending；dock 加 tabIndex=-1 + 自动聚焦 + role="status"。

### [P2] 正文行长 80 CJK 字，"扫读优先"没落地
1120px - 48 - 32 ≈ 1040px，13px 中文约 80 字/行。
修法：`.pc-action-text, .pc-gate-summary, .pc-gate-basis` 等 prose 加 `max-width:46em`，表格保持全宽。
