# v0.1.0 — 项目驾驶舱首个版本

左侧栏多一个「项目」，点开是一整页，只读回答三个问题：**到哪了 / 卡在哪 / 下一步做什么**。数据来自 trellis 任务与审核账本，插件**不写项目里任何文件**。

## 安装

```powershell
plugin_manager(action: "install_bundle", target: "git+https://github.com/hunyed15/project-cockpit.git#v0.1.0")
```

需要 DSH `>=0.2.2-rc.3 <0.3.0`，只有 Web profile 有意义。安装后刷新页面，左侧栏底部出现「项目」图标。

## 这个版本能做什么

**1. 下一步是唯一输出**
状态机给出唯一动作，附三段：动作名（人话）、指令原文（可直接执行、标识符等宽）、理由（为什么是它）。

| 条件 | 动作 |
|---|---|
| 有未处置 blocking | 修复并复检 |
| 有已修待复检 | 用 `range` 复检 |
| 从没审过 | 跑第一次 `full` |
| 全绿 | 跑提交门禁 |

**2. 卡在哪给出内容，不只是数字**
列出最多 3 条未处置问题：严重度 + 标题 + `文件:行`。

**3. 行动层：两步，诚实**
点「去对话发送」→ 跳回对话，输入框上方出现通栏（带项目名）→「填入输入框」/「发送」/「忽略」。
之所以是两步：DSH 当前**没有**向活跃会话注入用户消息的公开 API（`commands.execute` 只跑斜杠命令、不发给模型）。改为走浏览器侧已验证的 `inputActions.setDraft()/submit()`——多一次点击，换来"你看得见将要发出去的是什么"，且走的是你自己的发送通道。

**4. 数据不可信时，界面不说谎**
账本异常或读取失败时，整屏一起降级：chip 变「状态待确认」→ 下一步变「先确认数据」且主按钮禁用 → 阶段门变「待确认」→ 表格 `待修` 显示 `—`（不是绿色 0）。**"读不到"不会被翻译成"你没问题"。**

**5. 七道阶段门，推断且可审计**
想清楚 / 定规格 / 搭骨架 / 写代码 / 挑毛病 / 验效果 / 发出去。每道门都显示推断依据；「验效果 / 发出去」第一版恒未完成，进度条上用**虚线**表示"第二版才接入"，与"没做"区分。

## 数据来源与口径

| 数据 | 来源 |
|---|---|
| 任务状态、优先级、子任务 | `<project>/.trellis/tasks/*/task.json` |
| 审核轮次、处置 | 每个任务自己的 `review/history.jsonl`、`review-N.json`、`dispositions.jsonl`；无 `.trellis` 时回落 `.dsh/claude-review/ledger/review/` |
| 环境 | `.trellis/.version`、`.trellis/spec/**` |

bug 计数与 `@hunyed15/claude-code-review` 对齐：`failOn` 取报告 `meta.failOn`（缺失回退 `critical/important`）；处置必须轮次匹配，按 `key` 优先、无 `key` 按原始下标；`fixed/deferred/counter-evidence` 视为已处置。多任务各算各的账本，`totals` 求和。

## 权限边界

- 面板是 root scope，拿不到会话；项目来自**已登记工作区**，路由只接受 `workspaceRegistry` 里登记过的路径，其余 403。
- 只读：只有 `GET`（`POST` 被拒），不写项目文件、不写缓存。
- **插件路由不受 DSH Web 令牌保护**：`GET /` 返回 401，但同进程 `GET /project-cockpit/api/panel` 返回 200。它只监听 `127.0.0.1`，只返回已登记工作区的 trellis 元数据（任务标题、审核统计），不含文件内容、无写操作。**不要把端口暴露到局域网。**

## 已知限制

- 面板每 8 秒轮询，无增量推送；任务表无排序/筛选；超过 200 个任务只显示前 200（卡点数与阶段门仍按全量计算）。
- 待发送指令只在浏览器内存里，刷新即丢（可从面板重新生成）。
- 「想清楚」门按 spec 文件数**近似**判断 PRD 已建立（不解析 `prd.md` 内容），文案里明确标注"近似"。
- 记住上次看的项目存在 localStorage；换机器或清缓存后回到第一个工作区。

## 验证状态（如实标注）

- 单元测试 **116 个断言全绿**（`node --test`）：计数口径、读取器容错、阶段门、下一步状态机、面板模型、HTTP 路由、客户端静态检查。
- 真机验证：面板路由 200、`?path=` 未登记 → 403、`POST` → 405、字段与客户端读取一致；左栏图标 / 中央整页 / `conversation.input.dock` 三个插槽均已确认注册为 active。
- 视觉验证：仓库内自带 `tools/preview/`（真实 React + 真实 CSS + CDP 截图），已用它核查 360/768/1200px 无横向溢出，以及 blocking / warnings / error / empty / 多任务等状态。
- **未验证**：颜色对比度（预览用的是近似主题变量，需真机实测）；`blocking > 0` 在真实账本上的显示（本机历史审核全部 pass，该路径仅由真实形状的 fixture 覆盖）。
